YAML

インデントだけで構造を語る、設定ファイルの定番

ひとことでいうと

波括弧を使わず、インデント（字下げ）だけで階層構造を表現するデータ形式。

1

なぜ生まれた？

設定ファイルをJSONで書くとコメントを残せず、括弧やカンマの対応関係も見落としやすかった。人が手で書きやすく、意図を書き添えられる設定形式が求められた。

2

それまでどうしていた？

JSONでも設定は書けるが、コメントが書けず、括弧やカンマの数え間違いも起きやすい。

JSONYAML
見た目{ } と , が並ぶインデントのみ
コメント書けない# で書ける
向いている場面APIのレスポンス手で書く設定ファイル
3

YAML で何ができるようになった？

手書きしやすい設定ファイルが書ける
コメントを残しながら設定できる
GitHub ActionsやCIの定義に使われる
ひとことメモ

YAMLは「YAML Ain't Markup Language」の再帰的な略称。
読みやすさ重視な分、インデントのミスがそのまま解釈エラーになるので、エディタのタブ設定表示は必須。
