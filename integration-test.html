501

Integration Test

つなぎ目で、初めて起きる事故を拾う

ひとことでいうと

複数のモジュールや、DB・APIなどの外部をつないだ状態で、連携が正しいかを確かめるテスト。

1

なぜ生まれた？

単体では正しくても、つなぐと型やトランザクション、設定の食い違いで落ちることがある。
「結合した姿」を見るテストが必要になった。

2

それまでどうしていた？

ユニットテストは通るのに、実際にDBを繋ぐと落ちる——を本番近くで初めて知る、がよくあった。

単体だけ／手動結合Integration Test
見る範囲部品の内側部品の境界と相互作用
依存モックで消しがち本物かそれに近いものを使う
速さ非常に速いユニットより遅い
見つかるバグロジック誤り配線・設定・契約のずれ
3

Integration Test で何ができるようになった？

モジュール間の契約ずれを早期に見つけられる
DBやAPIとの実連携を検証できる
E2Eより狭く、原因を追いやすい
ひとことメモ

「どこからが結合か」は宗教戦争になりやすい。
チームで境界を一文で定義しておくだけで、テストの粒度が安定する。
