JSON

「閉じタグの海」から抜け出したデータの書き方

ひとことでいうと

{ }と[ ]だけで表現する、JavaScriptのオブジェクトそのままの見た目のデータ形式。

1

なぜ生まれた？

APIやシステム間でのデータ交換にXMLを使うと、開始・終了タグの記述量が多くなり、パース処理も複雑になりがちだった。より簡潔に書けるデータ形式が求められていた。

2

それまでどうしていた？

2000年代まではXMLで構造化データをやりとりするのが主流だった。

XMLJSON
書き方開始・終了タグが必須{ } と [ ] だけ
読みやすさネストが深いと追いづらいJSのオブジェクトと同じ感覚
パース専用パーサーが必要JSならそのまま扱える
3

JSON で何ができるようになった？

設定やAPIレスポンスを簡潔に表現
言語をまたいでそのままやりとり
配列とオブジェクトだけで大抵表現できる
ひとことメモ

JSONは「JavaScript Object Notation」の略。
名前の通りJSのオブジェクトそのままの書き方だけど、今はJS以外の言語でも共通語として使われている。
