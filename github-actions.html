GitHub Actionsギットハブアクションズ

ひとことでいうと

GitHub上でCI/CDワークフローを回す仕組み。

1

なぜ生まれた？

コードを置くGitHubとは別にCIサービスを設定するのは手間だった。
そこでGitHub自身が、イベントを契機に処理を走らせる機能を持った。

2

それまでどうしていた？

外部のCIサービスや、自前のサーバーでCIを動かしていた。

外部CI・自前CIActions
設定場所別サービスの画面リポジトリ内YAML
連携の手間GitHubとの連携設定最初から統合済み
起動の契機pollingやhook設定push・PR等のイベント
運用サーバーの管理GitHubが環境を提供
3

GitHub Actions で何ができるようになった？

pushやPRで自動実行
YAMLで処理をコード管理
PR上でテスト結果を確認
ひとことメモ

ワークフローは .github/workflows 配下のYAMLに書く。
「Actions」「GHA」と略される。無料枠には上限があり、超えると課金対象になる。
