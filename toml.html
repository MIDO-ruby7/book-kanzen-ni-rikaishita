TOML

「インデントミスに悩みたくない」から生まれた設定形式

ひとことでいうと

key = value の並びで設定を書く、あいまいさの少ないシンプルな設定ファイル形式。

1

なぜ生まれた？

パッケージ管理ツールの設定ファイルには、複雑な入れ子構造よりも誰が読んでも一意に解釈できるシンプルな記法が向いていた。あいまいさの少ない設定形式が求められた。

2

それまでどうしていた？

YAMLは表現力が高い分、インデントの深さやリストの書き方に複数の流儀があり、ツールによって解釈が割れることがあった。

YAMLTOML
書き方の自由度高い（複数の書き方がある）低い（迷いにくい）
ネスト表現インデントで表現[section] で区切る
向いている場面複雑な設定・CI定義ツールの設定ファイル1枚
3

TOML で何ができるようになった？

key = value で直感的に書ける
Cargo.tomlなどパッケージ設定の定番
書き方のブレが少なく読み間違えにくい
ひとことメモ

名前の通り「誰が読んでも解釈がブレない」ことを目指して設計されている。
